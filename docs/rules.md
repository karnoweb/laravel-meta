# قواعد

## نوشتن

هر `setMeta` در تراکنش connection مدل اجرا می‌شود. ردیف root با `lockForUpdate` قفل می‌شود. اگر ردیف نباشد، insert داخل savepoint انجام می‌شود. برخورد با یکتایی (`UniqueConstraintViolationException` یا SQLSTATE `23000` / `23505`) باعث قفل مجدد همان ردیف می‌شود، نه ساخت root دوم.

`setMetas` یک تراکنش است و کلیدها را به ترتیب نام قفل می‌کند.

Deadlock (`DeadlockException` یا SQLSTATE `40001` / `40P01`) تا سه تلاش با `usleep(20000 * attempt)` تکرار می‌شود. بقیه خطاها تکرار نمی‌شوند.

SQLite این قفل را اثبات نمی‌کند. تست هم‌زمانی فقط با `META_INTEGRATION=1` روی MySQL یا PostgreSQL اجرا می‌شود.

## نسخه‌بندی

- کلید جدید بدون `versioned: true` عادی است.
- کلید موجود mode را به ارث می‌برد.
- خاموش کردن کلید نسخه‌دار ممنوع است.
- ارتقا، مقدار فعلی را نسخه اول می‌کند و بعد مقدار جدید را می‌نویسد.
- backdate قبل از ارتقا ممنوع است.
- مقدار جاری: `effective_at DESC, id DESC` بین نسخه‌های غیرحذف و غیرآینده.
- tombstone یعنی غایب، بدون برگشت به نسخه قبلی.

## null و حذف

نبود کلید، `null` صریح، رشته خالی، `false`، و tombstone پنج وضعیت جدا هستند.

حذف نرم مدل متادیتا را نگه می‌دارد.

حذف سخت یا `forceDelete()` فقط اگر `meta.purge_on_force_delete` برابر `true` باشد root و نسخه‌ها را در branch جاری پاک می‌کند. پیش‌فرض `false` است.

`purge` و `purgeMany` حذف root و نسخه را در یک تراکنش روی connection همان گروه انجام می‌دهند. مدل‌های چند connection یک تراکنش سراسری نیستند. شناسه‌ها ۵۰۰تایی حذف می‌شوند. اگر حذف root شکست بخورد، حذف نسخه‌های همان تراکنش برمی‌گردد.

`Model::query()->where(...)->delete()` رویداد مدل را اجرا نمی‌کند و purge نمی‌شود. برای حذف دسته‌ای `Meta::purgeMany($models)` را در branch درست صدا بزنید.

## مدل ذخیره‌نشده

اگر مدل `save` نشده باشد، متادیتا نوشته نمی‌شود و مدل هم ذخیره نمی‌شود.

## کلید و شناسه

کلید حداکثر ۱۲۰ کاراکتر، UTF-8، بدون کاراکتر کنترل. شناسه مدل حداکثر ۶۴ و morph class حداکثر ۱۵۰ کاراکتر. هیچ‌کدام بی‌صدا کوتاه نمی‌شوند.

کلید متادیتا attribute الکوئنت نمی‌سازد. `getAttribute` و `setAttribute` مدل دست نمی‌خورند.
